Section 03

Agent Execution Flow

Ten specialised AI agents execute in sequence. Each agent receives structured inputs, produces documented outputs, and is independently auditable.

Agent 01

Repository Intake

Discovers and catalogues all source repository assets — ACE projects, BAR files, ESQL, XSD, WSDL, and configuration artefacts.

Input: Source Repository
Output: Intake Manifest
Agent 02

Dormancy Intelligence

Analyses deployment history, traffic patterns, and dependency signals to determine whether the service is actively used or dormant.

Input: Intake Manifest
Output: Dormancy Report
Agent 03

Framework Baseline

Establishes the authoritative Spring Boot standards — dependency versions, project structure, coding conventions, and security configurations.

Input: Dormancy Report
Output: Framework Baseline
Agent 04

ACE Analysis

Deeply parses IBM ACE message flows, ESQL logic, XML maps, routing patterns, and connector configurations to produce a semantic understanding of the application.

Input: Repository Assets
Output: ACE Analysis Report
Agent 05

Migration Specification

Translates the ACE Analysis into a structured migration blueprint — mapping each ACE construct to its Spring Boot equivalent with justification.

Input: ACE Analysis Report
Output: Migration Specification
Agent 06

Planning

Defines the migration strategy, execution order, risk mitigations, rollback procedures, and resource estimates from the approved specification.

Input: Migration Specification
Output: Migration Plan
Agent 07

Code Generation

Generates the complete Spring Boot service — controllers, services, models, configurations, tests, and build scripts — from the approved migration plan.

Input: Migration Plan
Output: Spring Boot Codebase
Agent 08

Differential Testing

Runs identical request payloads against the legacy ACE service and the new Spring Boot service, comparing outputs field-by-field and flagging discrepancies.

Input: Both Services
Output: Variance Report
Agent 09

Root Cause Analysis

Investigates each variance to identify whether it originates from a code defect, a data transformation difference, or an acceptable behavioural change.

Input: Variance Report
Output: RCA Report
Agent 10

Remediation

Generates targeted code corrections and configuration adjustments to resolve variances identified by the RCA Agent. Packages remediation evidence for review.

Input: RCA Report
Output: Remediation Package

Section 07

Clarification Mechanism

When the AI cannot determine intent from available evidence, it raises a structured clarification rather than guessing. The pipeline pauses until a human answers.

1
AI Identifies Ambiguity
Agent encounters a situation where it cannot make a reliable determination — missing data, contradictory signals, or a decision outside its authority.
2
Clarification Created
A structured clarification record is created and linked to the migration. The pipeline transitions to a CLARIFICATION_PENDING state.
3
Human Notified & Responds
The designated stakeholder receives the clarification with full context. They provide a structured response — a decision, directive, or additional information.
4
Pipeline Resumes
The clarification is resolved, the response is recorded in the audit trail, and the AI agent continues from the point it paused.
Live Example — Clarification #CL-0042
No ACE Message Flow Detected
Agent Observation
Repository scanned. No .msgflow files found in /ACE_Project. Cannot proceed with ACE Analysis without confirmed message flow entry points.
Clarification Question
The ACE project appears to use dynamically loaded flows stored outside the standard path. Should the pipeline proceed by scanning the entire repository, or should additional paths be provided?
Human Response — Service Owner
PROCEED — Scan entire repository. Additional path: /src/main/flows
Resolved · Pipeline resumed · Recorded in audit trail

Section 09

AI + Human Governance

The platform is built on a clear division of responsibility. AI agents handle the analytical work at scale and speed; humans retain authority over every consequential decision.

AI Generates
  • → Discovers and catalogues source repositories automatically
  • → Parses ACE flows, ESQL, and XML maps at machine speed
  • → Produces migration specifications and implementation plans
  • → Generates Spring Boot code from structured blueprints
  • → Runs differential tests and identifies variances precisely
  • → Performs root cause analysis and proposes remediation
  • → Assembles complete evidence packages automatically
Humans Decide
  • ✓ Whether the service should be migrated at all (G0)
  • ✓ Whether framework standards are organisationally correct (G1)
  • ✓ Whether the AI understood the ACE application correctly (G2)
  • ✓ Whether the migration plan is acceptable (G3)
  • ✓ Whether variances are acceptable or must be resolved (G4)
  • ✓ Whether the solution is ready for production promotion (G5)
  • ✓ All clarifications requiring business or domain judgement
Every action is auditable.

Every AI agent execution, every human approval, every clarification response, and every governance decision is recorded with a timestamp, actor identity, and full artefact linkage. The audit record is immutable and available for compliance review at any point in the migration lifecycle.

Section 10

Client Demo Script

A plain-language narrative for presenting ACE Modernization Accelerator to stakeholders, clients, and decision-makers.

"ACE Modernization Accelerator automatically discovers the source IBM ACE application, catalogues its assets, and determines whether the service is actively used in production. It then establishes the target Spring Boot standards and performs a deep analysis of every ACE message flow, ESQL transformation, and XML mapping. From this analysis, AI agents generate a structured migration specification and a detailed implementation plan — both of which are reviewed and approved by your architects and product owners before a single line of code is produced.

Once approved, the platform generates a complete, production-ready Spring Boot service. That service is immediately subjected to differential testing — every input payload is executed against both the original ACE service and the new Spring Boot service, and every discrepancy is logged, root-cause analysed, and presented to your QA team for acceptance.

Throughout this entire process, the platform pauses at six named governance gates where designated approvers — your service owners, architects, SMEs, product owners, QA leads, and release managers — review the AI-generated evidence and make the authoritative decisions. The AI cannot advance past any gate without explicit human approval. Every decision, every artefact, and every action is recorded in a permanent audit trail that supports your compliance, risk, and governance requirements."

— Recommended delivery narrative for executive and client presentations
